# Especificación de Requerimientos: REP-3532

## 1. Contexto y Objetivo
Implementar la sincronización asíncrona de los consentimientos de términos y privacidad entre el cliente web y la base de datos PostgreSQL en Supabase (tabla `terms_consents`), con soporte multi-dispositivo y fallback offline resiliente en `localStorage`.

---

## 2. Historias de Usuario
- **Como** vecina que utiliza múltiples dispositivos (computadora y celular),
- **Quiero** que mi consentimiento otorgado se sincronice en la nube,
- **Para** no tener que volver a aceptar los términos en cada nuevo dispositivo ni sufrir bloqueos innecesarios.

- **Como** auditor legal del sistema Reportalo,
- **Quiero** contar con un registro inmutable de cada aceptación con versión, fecha y permisos otorgados,
- **Para** cumplir con la Ley Nacional N° 25.326 de Protección de Datos Personales.

---

## 3. Criterios de Aceptación

1. **AC-01 (Persistencia Asíncrona en Supabase):**
   - Al invocar `recordTermsAcceptance(userId, permissions)`, se genera e inserta un registro en `public.terms_consents` con `user_id`, `terms_version`, `accepted_at`, `permissions` (JSONB) y `metadata` (JSONB).

2. **AC-02 (Copia Local y Resiliencia Offline):**
   - Siempre se persiste una copia local en `localStorage` con la misma estructura para garantizar 0ms de latencia en la UI y funcionamiento en caso de corte de conexión.

3. **AC-03 (Sincronización en Inicio de Sesión):**
   - Al autenticarse (`AuthContext`), se consulta en segundo plano `syncTermsConsentWithRemote(userId)` para restaurar el consentimiento si el usuario viene de otro dispositivo.

4. **AC-04 (Manejo de Errores y Tolerancia a Fallos):**
   - Si Supabase está inaccesible o la red falla, la operación captura el error de forma segura sin interrumpir el flujo del usuario.
