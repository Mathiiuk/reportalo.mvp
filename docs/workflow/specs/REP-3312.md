# Specification — REP-3312

## 1. Objetivo

Corregir gaps de seguridad identificados en la auditoría de REP-2100 (Login con Google): integrar validación de redirect URL, agregar CSP y HSTS headers.

## 2. Problema actual

- `validateRedirectUrl()` está definida en `supabase.js` pero nunca se llama desde `signInWithGoogle()`
- `vercel.json` no tiene `Content-Security-Policy` (previene XSS/exfiltración de tokens)
- `vercel.json` no tiene `Strict-Transport-Security` (fuerza HTTPS)

## 3. Resultado esperado

- `signInWithGoogle()` valida el redirect URL antes de ejecutar OAuth
- Headers de seguridad completos en vercel.json
- Sin regresiones en el flujo OAuth

## 4. Alcance

### Incluido
- Integrar `validateRedirectUrl()` en `signInWithGoogle()`
- CSP header en vercel.json
- HSTS header en vercel.json

### No incluido
- Tests E2E del flujo OAuth (futuro REP)
- Eliminación de código muerto (validateRedirectUrl se integra, no se elimina)

## 5. Criterios de aceptación

- [x] AC-01: signInWithGoogle valida redirect URL
- [x] AC-02: CSP header presente
- [x] AC-03: HSTS header presente
- [x] AC-04: Flujo OAuth no roto

## 6. Dependencias

- Vercel deployment para verificar headers

## 7. Trazabilidad

Audit REP-2100 → Gaps #1, #2, #3
