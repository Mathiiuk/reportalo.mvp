# Specification — REP-3520: Mantener y cerrar sesión de forma segura

## 1. Objetivo

Como ciudadano autenticado, quiero que Reportalo mantenga mi sesión activa y me permita cerrarla de forma segura para acceder sin fricción y proteger mi cuenta cuando termino de usarla.

## 2. Problema actual

La app tiene sesión persistente vía Supabase y un botón de logout en MapaPage, pero:
- PerfilPage es un placeholder sin UI ni botón de cerrar sesión.
- No hay feedback al usuario cuando la sesión expira (redirección silenciosa a `/`).
- El flujo de sesión activa, logout y expiración no está documentado ni validado.

## 3. Estado actual de la implementación

### Lo que SÍ funciona
| Componente | Estado | Detalle |
|------------|--------|---------|
| `AuthContext` | ✅ | `getSession()` hidrata desde localStorage, `onAuthStateChange` escucha eventos |
| `supabase.js` | ✅ | `persistSession: true`, `autoRefreshToken: true`, `detectSessionInUrl: true` |
| `ProtectedRoute` | ✅ | Spinner durante loading, redirect a `/` si no autenticado |
| `MapaPage` logout | ✅ | `signOut()` + `resetOnboarding()` + toast + navigate `/` |
| `HomePage` redirect | ✅ | Si sesión válida + onboarding completed → `/map` |

### Lo que FALTA
| # | Componente | Problema | Impacto |
|---|-----------|----------|---------|
| 1 | `PerfilPage` | Placeholder `<UnderConstruction>`, sin botón de logout | El usuario no puede cerrar sesión desde su perfil |
| 2 | Sesión expirada | Redirección silenciosa a `/` sin toast | Confusión del usuario ("¿por qué me sacó?") |
| 3 | `signInWithEmail` | `AuthContext` no provee esta función, solo `signIn` (password) | Magic link roto — solo Google funciona |
| 4 | Onboarding reset en expiración | No se llama `resetOnboarding()` al expirar sesión | Estado inconsistente |
| 5 | Error boundary auth | `catch` en AuthContext solo setea `loading=false` sin limpiar `user` | Posible estado stale |

## 4. Criterios de aceptación

- [ ] **AC-01**: Sesión persiste al recargar la app (Supabase localStorage + autoRefreshToken).
- [ ] **AC-02**: ProtectedRoute redirige a `/` si no hay sesión válida, mostrando spinner durante loading.
- [ ] **AC-03**: Botón "Cerrar sesión" visible y accesible en PerfilPage.
- [ ] **AC-04**: Logout limpia: sesión Supabase (`signOut`) + onboarding localStorage (`resetOnboarding`) + redirige a `/`.
- [ ] **AC-05**: Sesión expirada muestra toast "Tu sesión expiró. Volvé a iniciar sesión." y redirige a `/`.
- [ ] **AC-06**: HomePage redirige a `/map` si sesión válida y onboarding completado (sin re-autenticar).
- [ ] **AC-07**: Listener `onAuthStateChange` actualiza `user` y `session` en tiempo real.

## 6. Restricciones

- Usar Supabase Auth SDK (no custom JWT).
- No exponer service roles ni secretos en frontend.
- Compatible con iOS Safari y Android Chrome (PWA standalone).
- Touch targets mínimo 48x48px (mobile-pwa-architect).

## 7. Dependencias

- Supabase Auth: `signInWithGoogle`, `signOut`, `onAuthStateChange`, `getSession`
- OnboardingContext: `resetOnboarding`
- react-router-dom: `useNavigate`, `Navigate`, `useLocation`
- sonner: `toast`

## 8. Riesgos

| Riesgo | Impacto | Mitigación |
|--------|---------|------------|
| Magic link no implementado | Alto | Solo Google OAuth funciona; documentar como known issue |
| Onboarding en localStorage se pierde | Bajo | Comportamiento aceptable para MVP; futuras versiones usarán backend |
| Error en `getSession()` deja estado stale | Medio | Agregar try/catch robusto en AuthContext init |
