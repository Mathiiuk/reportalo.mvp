# Specification — REP-2100

## 1. Objetivo

Implementar la autenticación de usuarios ciudadanos mediante **Google OAuth** en Reportalo MVP, utilizando Supabase Auth y permitiendo un acceso rápido y seguro sin necesidad de recordar contraseñas.

## 2. Problema actual

Los ciudadanos necesitan una forma inmediata y sin fricción para ingresar a Reportalo y gestionar el seguimiento de sus reportes. No existía la pantalla de bienvenida/onboarding ni la pantalla de login con proveedor Google integradas en la aplicación React.

## 3. Resultado esperado

1. Una pantalla de bienvenida (Onboarding/Welcome) que presenta la propuesta de valor de Reportalo con botón "Comenzar".
2. Una pantalla de acceso (Login) con opción "Continuar con Google", maquetado del input de correo para futuros enlaces mágicos y mensaje de privacidad y resguardo de identidad.
3. Al accionar "Continuar con Google", se inicia el flujo OAuth con Supabase.
4. Al autenticarse con éxito, se redirige al usuario a la pantalla destino protegida (pantalla en blanco post-login) y se limpian los fragmentos de autenticación de la URL.
5. Si el flujo es cancelado o falla, se notifica claramente al usuario manteniéndolo en la pantalla de acceso.

## 4. Alcance

### Incluido
- Pantalla de bienvenida (Screen 1) con diseño visual provisto (tipografía Manrope, Material Symbols Rounded, gradiente azul).
- Pantalla de acceso (Screen 2) con botón de retorno (`arrow_back`), branding de Reportalo, botón "Continuar con Google", maquetado visual de "Tu correo" / "Enviarme un enlace" y tarjeta de resguardo de identidad.
- Integración de Supabase Client (`signInWithOAuth` con provider `google`).
- `AuthProvider` y hook `useAuth` para gestionar estado de sesión, redirección y sanitización de URL.
- Pantalla de destino post-login (página en blanco/dashboard simple con información de usuario autenticado y botón para cerrar sesión).
- Pruebas unitarias con Vitest y Testing Library.
- Soporte mobile-first PWA (safe-areas, responsive 320px+, touch targets $\ge 48\text{px}$).

### No incluido
- Envío y validación de Magic Link (reservado para `feat/REP-2101-login-magic-link`).
- Módulos avanzados de mapa o creación de reportes posteriores (alcance de siguientes HUs).

## 5. Criterios de aceptación

- [x] **AC-01**: La pantalla de acceso ofrece la opción "Continuar con Google" respetando tipografía Manrope, iconos y paleta.
- [x] **AC-02**: Al seleccionar la opción, se inicia el flujo OAuth en Supabase con Google.
- [x] **AC-03**: Una autenticación válida crea/recupera la sesión del ciudadano y lo dirige a la pantalla post-login.
- [x] **AC-04**: Si la autenticación se cancela o falla, el usuario permanece en la pantalla de acceso y recibe un mensaje comprensible.
- [x] **AC-05**: No se exponen tokens ni información sensible en la interfaz o URL final.
- [x] **AC-06**: El flujo es compatible con mobile-first y estándares PWA.
- [x] **AC-07**: QA valida casos exitosos y de error mediante tests automatizados.

## 6. Restricciones

- React 18, Vite, Tailwind CSS.
- Backend: Supabase Auth.
- Fuentes: Manrope e iconos Material Symbols Rounded vía Google Fonts.

## 7. Dependencias

- `@supabase/supabase-js`
- `react-router-dom`
- `vitest`, `@testing-library/react`

## 8. Riesgos y Mitigación

- **Riesgo:** Persistencia de fragmentos OAuth (`#access_token=...`) en navegadores móviles.
  - **Mitigación:** Sanitizar `window.history.replaceState` en el listener de inicialización de sesión.
- **Riesgo:** Falta de credenciales de Supabase en entornos locales sin `.env`.
  - **Mitigación:** Manejar excepciones en el cliente de autenticación con feedback claro en lugar de error en tiempo de renderizado.

## 9. Impacto

### Frontend
- Nuevos componentes: `WelcomeScreen`, `LoginScreen`, `BlankAppScreen`, `AuthProvider`, `SupabaseClient`.
- Configuración de Tailwind, Vite, Vitest y Manifest PWA.

### Backend
- Delegado a Supabase Auth (configuración de proveedor Google en proyecto Supabase).

### Seguridad
- Sanitización de URL post-redirección OAuth.
- No persistencia insegura de tokens en frontend fuera del almacenamiento estándar seguro de Supabase.

## 10. Preguntas / Resoluciones

- *Destino post-login:* Resuelto con página en blanco / dashboard básico.
- *Transición entre pantallas:* Confirmada (Comenzar -> Login, Volver -> Comenzar).
- *Magic link:* Dejado solo a nivel maquetado visual para REP-2101.
