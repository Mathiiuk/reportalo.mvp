# Specification — REP-3310

## 1. Objetivo

Persistir el flag de onboarding completado en los metadatos del usuario de Supabase (DB) para que usuarios existentes entren directo a /map sin ver onboarding, incluso en nuevos dispositivos o después de limpiar cache.

## 2. Problema actual

El flag de onboarding (`onboarding_status`) se almacenaba únicamente en `localStorage`. Esto causaba que:

- Usuario existente en **nuevo dispositivo** → ve onboarding otra vez
- Usuario que **limpia cache** → ve onboarding otra vez
- No hay forma de saber en el servidor si el usuario ya completó onboarding

## 3. Resultado esperado

- Usuarios registrados entran directo a `/map` sin pasar por onboarding
- El flag persiste en la DB de Supabase (`user.user_metadata.onboarding_completed`)
- Migración automática para usuarios con flag solo en localStorage

## 4. Alcance

### Incluido
- Guardar `onboarding_completed: true` en Supabase user metadata al completar onboarding
- Verificar metadata de Supabase ANTES de localStorage en HomePage
- Sincronización automática localStorage → Supabase

### No incluido
- Migración batch de usuarios existentes (se hace on-demand)
- Cambios en el flujo de onboarding en sí

## 5. Criterios de aceptación

- [x] AC-01: PermisosPage guarda flag en Supabase user metadata
- [x] AC-02: Flag guardado en handleContinue y handleSkip
- [x] AC-03: HomePage verifica Supabase metadata primero
- [x] AC-04: Sincronización automática localStorage → Supabase
- [x] AC-05: Usuario existente en nuevo dispositivo entra a /map
- [x] AC-06: Nuevo usuario pasa por onboarding completo

## 6. Restricciones

- No romper flujo de onboarding para nuevos usuarios
- Mantener compatibilidad con usuarios existentes

## 7. Dependencias

- @supabase/supabase-js ^2.49
- Supabase Auth con user metadata

## 8. Riesgos

- Usuarios pre-cambio serán tratados como nuevos una vez (se sincroniza automáticamente)

## 9. Impacto

### Frontend
- 2 archivos modificados: PermisosPage.jsx, HomePage.jsx

### Backend
- Sin cambios (Supabase gestiona metadata)

### Database
- Campo `onboarding_completed` en `raw_user_meta_data` (auto-creado por Supabase)

### Seguridad
- Sin impacto negativo

## 10. Preguntas / incertidumbres

- ¿Limpiar localStorage después de sincronizar a Supabase? (decisión: mantener como fallback)
