# Specification — REP-3308

## 1. Objetivo

Auditar y mejorar el frontend de Reportalo V2 contra las reglas del master-workflow, enfocándose en consistencia de diseño, seguridad, PWA, accesibilidad y arquitectura de componentes.

## 2. Problema actual

El frontend presentaba múltiples inconsistencias acumuladas durante el desarrollo iterativo:
- Credenciales Supabase hardcoded como fallback (riesgo de seguridad)
- Service Worker sin registrar (PWA incompleta)
- CSS de MapLibre importado dos veces (duplicación)
- Dos implementaciones de la página de permisos (PermissionsPage obsoleta, PermisosPage correcta)
- Inline styles masivos en HomePage y OnboardingPage en vez de Tailwind
- Fuente principal inconsistente (Tailwind decía Inter, index.html cargaba Manrope)
- Marker leak en MapaPage al geolocalizar múltiples veces
- Sin ErrorBoundary global (un error de render mata toda la app)
- OnboardingContext sin validación de valores de localStorage

## 3. Resultado esperado

Frontend consistente, seguro y accesible que cumpla con los estándares del master-workflow:
- Seguridad: sin credenciales hardcoded
- PWA: manifest completo y SW registrado
- Consistencia: Tailwind-first, fuente Manrope unificada
- Accesibility: aria-labels, botones semánticos, touch targets >=48px
- Robustez: ErrorBoundary, validación de estado

## 4. Alcance

### Incluido
- Seguridad: eliminación de fallbacks hardcoded
- PWA: SW registration, manifest completo
- Arquitectura: unificación de rutas, ErrorBoundary
- Consistencia: Tailwind migration, font unification
- Accesibilidad: aria-labels, semantic buttons
- Bugs: marker leak, imagen rota, comentarios duplicados
- UX: loading states en botones de acción

### No incluido
- Migración completa de todos los inline styles (solo páginas principales)
- Tests E2E
- Performance optimization (code splitting mejorado)
