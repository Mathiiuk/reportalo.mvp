# Test Plan — REP-2100

## 1. Objetivo

Validar de manera automatizada y reproducible la funcionalidad de la pantalla de bienvenida, pantalla de acceso, inicio de sesión mediante Google OAuth con Supabase, manejo de errores y redirección segura post-autenticación.

## 2. Riesgos a validar

1. El botón "Continuar con Google" debe invocar correctamente `supabase.auth.signInWithOAuth` con el proveedor `'google'`.
2. Si la autenticación falla, se debe renderizar un mensaje de error claro y accesible para el usuario.
3. Al existir una sesión activa, el usuario debe acceder a la pantalla destino protegida.
4. La navegación hacia atrás desde la pantalla de login debe regresar a la pantalla de bienvenida.
5. Los fragmentos o query params residuales de OAuth deben removerse de la URL sin comprometer la sesión.

## 3. Casos de prueba unitarios e integración (Vitest)

- [x] **UT-01:** `WelcomePage` renderiza el título "Reportalo", los tres elementos diferenciales (anónimo, IA, seguimiento) y el botón "Comenzar".
- [x] **UT-02:** Al pulsar "Comenzar" en `WelcomePage`, navega hacia la ruta `/login`.
- [x] **UT-03:** `LoginPage` renderiza el botón "Continuar con Google", el maquetado de correo y el mensaje de protección de identidad.
- [x] **UT-04:** Al pulsar "Continuar con Google", se ejecuta `signInWithGoogle` llamando a Supabase con `{ provider: 'google' }`.
- [x] **UT-05:** Si la llamada a Google OAuth retorna error, se muestra el banner de notificación de error al usuario en pantalla.
- [x] **UT-06:** Al hacer clic en el botón de retroceso (`arrow_back`), el usuario regresa a la pantalla de bienvenida.
- [x] **UT-07:** Si el usuario ya está autenticado, la aplicación lo redirige automáticamente a la pantalla post-login `/app`.
- [x] **UT-08:** `BlankAppPage` permite visualizar la sesión y ofrece la acción de cerrar sesión.

## 4. Evidencia requerida

- Ejecución de `npx vitest run` con 100% de tests pasando (8/8 tests en verde).
- Ejecución de `npx vite build` completando el bundle de producción sin fallos.
