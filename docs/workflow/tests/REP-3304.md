# Test Plan — REP-3304: Configurar Vercel Preview por Rama

## 1. Objetivo de las Pruebas

Verificar que la integración entre GitHub y Vercel dispare correctamente las vistas previas en cada Pull Request y que el enlace generado sea accesible para validación por parte de QA (Ivo).

## 2. Casos de Prueba

### TC-01: Validación de Sintaxis y Archivos Locales
- **Objetivo**: Asegurar que `docs/workflow/tasks/REP-3304.yml` y `vercel.json` no tengan errores de formato.
- **Resultado Esperado**: Pasaron validación con PyYAML y JSON parse sin advertencias ni errores.

### TC-02: Creación de Pull Request y Disparo de Preview en Vercel
- **Objetivo**: Verificar que al publicar la rama `feat/REP-3304-vercel-preview` y abrir un PR hacia `main`, Vercel detecte el evento.
- **Resultado Esperado**: Vercel inicia el build y marca el check de commit en GitHub como `vercel — Deployment completed`.

### TC-03: Comentario del Bot de Vercel en el PR
- **Objetivo**: Confirmar que el bot de Vercel inserte el enlace de preview en el PR.
- **Resultado Esperado**: Comentario visible en el PR con la URL del preview (`https://...vercel.app`).

### TC-04: Acceso Público sin Login para QA (Ivo)
- **Objetivo**: Comprobar que Ivo puede abrir la URL de preview desde una ventana de incógnito o sin sesión iniciada en Vercel.
- **Resultado Esperado**: La página carga inmediatamente sin solicitar inicio de sesión ni contraseña.
