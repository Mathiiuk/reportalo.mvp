# REP-3607 — Plan de Tests: Términos modo consultivo desde Perfil

## Escenarios BDD

### Feature: Consulta de T&C desde Perfil en modo lectura

```gherkin
Feature: Consulta de Términos y Condiciones desde Perfil
  Como ciudadano autenticado
  Quiero poder consultar los T&C desde mi perfil
  Sin que eso modifique mi estado de consentimiento ni me pida aceptar de nuevo

  # ────────────────────────────────────────────────
  # Escenario 1: T&C vigentes ya aceptados
  # ────────────────────────────────────────────────
  Scenario: Usuario con T&C vigentes consulta desde Perfil
    Given que el usuario tiene los T&C vigentes (v1.3) aceptados en localStorage
    And se encuentra en /perfil
    When presiona "Revisar términos y permisos"
    Then navega a /terminos con state { consultaDesde: 'perfil' }
    And no ve el checkbox de aceptación
    And no ve el botón "Aceptar y continuar"
    And no ve el botón "Rechazar"
    And ve el banner verde "Ya aceptaste la versión vigente"
    And ve la versión aceptada (v1.3) y la fecha de aceptación
    And ve el botón "Volver a mi perfil"
    And el estado en localStorage no fue modificado

  # ────────────────────────────────────────────────
  # Escenario 2: T&C desactualizados, visita desde Perfil
  # ────────────────────────────────────────────────
  Scenario: Usuario con T&C desactualizados consulta desde Perfil
    Given que el usuario tiene los T&C versión v1.2 aceptados (desactualizado)
    And se encuentra en /perfil
    When presiona "Revisar términos y permisos"
    Then navega a /terminos con state { consultaDesde: 'perfil' }
    And no ve el checkbox de aceptación
    And no ve el botón "Rechazar"
    And ve el banner azul "Hay una nueva versión disponible"
    And el mensaje indica que la re-aceptación se pedirá al publicar un reporte
    And el estado en localStorage no fue modificado

  # ────────────────────────────────────────────────
  # Escenario 3: Primer ingreso (sin aceptación previa) — flujo intacto
  # ────────────────────────────────────────────────
  Scenario: Usuario sin aceptación accede a /terminos por flujo de onboarding
    Given que el usuario no tiene T&C aceptados
    And navega a /terminos sin state consultaDesde
    Then ve el flujo de aceptación completo (checkbox + "Aceptar y continuar" + "Rechazar")
    And no hay modo consultivo activo

  # ────────────────────────────────────────────────
  # Escenario 4: Usuario bloqueado — flujo obligatorio intacto
  # ────────────────────────────────────────────────
  Scenario: Usuario bloqueado es redirigido a /terminos
    Given que el usuario tiene noticesLeft < 0 (bloqueado)
    When el guard de App.jsx evalúa la ruta
    Then redirige a /terminos
    And en /terminos se muestra el banner rojo de bloqueo
    And se muestra el checkbox y los botones obligatorios
    And no hay modo consultivo activo (no hay state consultaDesde)

  # ────────────────────────────────────────────────
  # Escenario 5: Acceso directo a /terminos (barra de URL) con T&C aceptados
  # ────────────────────────────────────────────────
  Scenario: Usuario con T&C aceptados intenta acceder a /terminos directamente
    Given que el usuario tiene T&C vigentes aceptados
    And escribe directamente /terminos en la barra de URL (sin state)
    Then el guard en App.jsx lo redirige a /mapa
```
