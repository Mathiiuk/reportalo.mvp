# Implementation Plan — REP-3311

## 1. Resumen

Implementar autenticación por Magic Link (email OTP) usando Supabase, con callback route para verificar tokens y redirigir según estado del usuario.

## 2. Repositorio inspeccionado

- Stack: React 18, Vite 6, Supabase Auth, React Router DOM 7
- Branch base: feature/design-system-uiux
- CI: Vitest + Vite build

## 3. Cambios propuestos

### [MODIFY]
- `src/services/authService.js` — Agregar `signInWithEmail()` usando `supabase.auth.signInWithOtp()`. Mejorar `cleanAuthCallbackUrl()` para limpiar tokens de query params (token_hash, type, access_token).
- `src/context/AuthContext.jsx` — Importar y exponer `signInWithEmail` via context provider.

### [CREATE]
- `src/components/auth/AuthCallback.jsx` — Componente que maneja el redirect del magic link. Verifica sesión con `getSession()`, limpia URL, redirige a /map o /onboarding.

### [MODIFY]
- `src/routes/index.jsx` — Agregar ruta pública `/auth/callback` apuntando a AuthCallback.

## 4. Estrategia de implementación

1. authService: signInWithEmail con emailRedirectTo a /auth/callback
2. AuthContext: importar y exponer signInWithEmail
3. AuthCallback: componente de verificación con loading/error states
4. Routes: agregar /auth/callback como pública
5. Tests + Build

## 5. Seguridad

- Redirect URL validada (getSecureRedirectUrl)
- Tokens limpiados de URL después de verificación
- PKCE flow mantenido
- No exponer secrets en frontend
