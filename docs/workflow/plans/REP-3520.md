# Plan de Implementación — REP-3520: Mantener y cerrar sesión de forma segura

## 1. Resumen

Implementar el flujo completo de persistencia de sesión, cierre de sesión seguro y manejo de sesiones expiradas en la app Reportalo, incluyendo la creación de una pantalla de perfil funcional con botón de logout.

## 2. Componentes y Archivos Afectados

### Modificados
- `src/context/AuthContext.jsx` — Agregar manejo de sesión expirada
- `src/routes/ProtectedRoute.jsx` — Toast de sesión expirada
- `src/pages/PerfilPage.jsx` — Reemplazar placeholder con UI real + logout
- `src/pages/MapaPage.jsx` — Verificar logout existente

### Creados
- `docs/workflow/tasks/REP-3520.yml`
- `docs/workflow/specs/REP-3520.md`
- `docs/workflow/plans/REP-3520.md`

## 3. Estrategia de Implementación

### Paso 1: AuthContext — Manejo de sesión expirada
**Archivo:** `src/context/AuthContext.jsx`

Agregar listener `onAuthStateChange` que detecte el evento `SIGNED_OUT` (no solo el inicial) y:
- Setee `user = null`, `session = null`
- Muestre toast de sesión expirada
- Esto cubre AC-05 y AC-07

### Paso 2: ProtectedRoute — Toast informativo
**Archivo:** `src/routes/ProtectedRoute.jsx`

Cuando `!isAuthenticated` y `!loading`, antes de redirigir:
- Verificar si hay un flag de sesión expirada (viene del AuthContext)
- Mostrar toast: "Tu sesión expiró. Volvé a iniciar sesión."
- Redirigir a `/`

### Paso 3: PerfilPage — UI real con logout
**Archivo:** `src/pages/PerfilPage.jsx`

Reemplazar `<UnderConstruction>` con:
- Header con título "Mi perfil"
- Card con info del usuario (email, nombre si disponible)
- Botón "Cerrar sesión" con icono `logout`
- Handler que ejecuta: `signOut()` → `resetOnboarding()` → toast → `navigate('/')`
- Esto cubre AC-03 y AC-04

### Paso 4: Verificar logout en MapaPage
**Archivo:** `src/pages/MapaPage.jsx`

Ya existe `handleLogout` funcional. Verificar que:
- Llama `signOut()` correctamente
- Llama `resetOnboarding()`
- Muestra toast
- Navega a `/`

### Paso 5: HomePage — Verificar redirect post-login
**Archivo:** `src/pages/HomePage.jsx`

Verificar que el useEffect (líneas 37-48):
- Si `isAuthenticated && onboardingStatus === 'completed'` → `/map`
- Si `isAuthenticated && onboardingStatus !== 'completed'` → `/onboarding`
- Esto cubre AC-01 y AC-06

### Paso 6: Build y QA
- Ejecutar `npx vite build`
- Verificar que no hay errores de compilación
- Smoke test: login Google → onboarding → permisos → mapa → perfil → logout → landing

## 5. Estrategia de Rollback

Si algún cambio introduce regresiones:
1. Revertir el commit específico de la rama `feature/design-system-uiux`
2. Los cambios son encapsulados por archivo — rollback modular
3. No hay migraciones de DB ni cambios de infraestructura

## 6. Known Issues (Deferred)

- **Magic Link roto:** `signInWithEmail` no existe en AuthContext. Solo Google OAuth funciona. Requiere tarea separada para implementar `signInWithOtp`.
- **Onboarding en localStorage:** Se pierde al limpiar datos del navegador. Futuras versiones usarán backend tracking.
