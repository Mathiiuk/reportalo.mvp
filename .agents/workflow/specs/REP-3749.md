# Specification — REP-3749

## 1. Objetivo
Que el operador de un organismo de prueba abra desde la bandeja un reporte de su jurisdicción y vea qué pasó, dónde, qué fotos protegidas hay, el fundamento y el estado, sin recibir nunca identidad, `user_id`, contactos ni la foto original. Fuente: reglas v1.0 (REP-3876) §7, §8 y §9 (caso 5); Hernán 24/10 (sanciones con leyenda, número de caso); PM 25/10 (se mantienen las coordenadas).

## 2. Estado previo (verificado en staging, 28/10)
- El operador no lee `citizen_reports` (REP-3747). La bandeja (REP-3000) enlaza a `/panel/reportes/:id`, que da 404.
- `get_report_legal_foundation` (DEFINER, ya chequea quién atiende) devuelve las citas **sin el tipo de fragmento**. Las sanciones son citas de tipo `sancion`: 191 citas en 134 reportes.
- Las fotos se leen de `report_images`; el operador puede firmarlas por la regla de storage (`can_read_report_folder`, REP-3747).
- **No existe ningún dato de urgencia** en la base: no se muestra (el criterio dice «solo si consta»).
- No existe un número de caso legible (Hernán D4).

## 3. Resultado esperado
1. `citizen_reports.case_number`: correlativo `generated always as identity`. Los reportes existentes se numeran solos. Se suma a `get_panel_inbox`.
2. `get_panel_report_detail(id)` (DEFINER): si `profile_attends_report(auth.uid(), id)`, devuelve:
   - código, número de caso, fecha, categoría, estado y etiqueta;
   - descripción **redactada** (`redact_contact_info`);
   - localidad, coordenadas, calle y altura;
   - rutas de las fotos (anonimizadas) y fundamento con el tipo de cada cita.

   Si no lo atiende o no existe, devuelve `null`: mismo mensaje para los dos casos, para no revelar si existe.
3. Pantalla `/panel/reportes/:id` (dentro de `OperatorRoute`): datos, fotos firmadas, dirección o «Dirección no disponible», fundamento con normas y citas.
   - Sanciones con la leyenda «Sanción prevista por la norma; Reportalo no aplica sanciones»; si no hay ninguna, «La norma no registra sanción».
   - Fundamento pendiente o sin verificar, dicho tal cual.
   - Lugar reservado para las acciones de REP-3001.
4. Ajeno o inexistente: «Este reporte no está disponible para tu organismo». Error: mensaje con reintento.

## 4. Alcance
### Incluido
Lo de §3, y el número de caso en la bandeja.
### No incluido
Acciones y estados (REP-3001). Número de caso para el vecino (REP-3001, lectura ciudadana). Urgencia (no existe el dato).

## 5. Criterios de aceptación
- [ ] AC-01: el operador autorizado ve categoría, fecha, estado, calle y altura, fotos protegidas, descripción filtrada y fundamento si existe.
- [ ] AC-02: por UI o API, el operador no recibe identidad, `user_id`, `client_side_id`, contactos crudos ni la foto original.
- [ ] AC-03: el operador de CABA pidiendo un reporte de Avellaneda → `null` / «no disponible».
- [ ] AC-04: sin dirección → «Dirección no disponible»; fundamento pendiente → «pendiente». No se inventa nada.
- [ ] AC-05: inexistente o falla → mensaje veraz, sin datos de otro reporte.
- [ ] AC-06: sanciones con leyenda, o «La norma no registra sanción».

## 6. Restricciones
La frontera es la base: la RPC filtra y proyecta. La UI no recibe nada que no deba mostrar.

## 7. Dependencias
REP-3000 ✅, REP-3874 ✅, REP-3843: columnas aplicadas en staging (si un reporte no tiene dirección, se muestra «no disponible»). QA: REP-3758 bloque B.

## 8. Riesgos
`get_report_legal_foundation` se llama desde otra función DEFINER; `auth.uid()` se conserva (los claims del JWT), y se verifica en staging.
