# Especificación de Tarea: REP-2404 (Pipeline Server-Side de Cuarentena de Imágenes)

## 1. Descripción y Objetivos
Implementar la infraestructura y pipeline de backend en Supabase (Storage + Edge Function) para el aislamiento temporal y anonimización de evidencias fotográficas capturadas en el flujo ciudadano.

El pipeline actúa como una barrera de cuarentena estricta (Privacy by Design / Anexo C — Arquitectura v2):
- Ninguna fotografía original llega al almacenamiento durable ni es accesible públicamente.
- Las imágenes crudas se reciben en un bucket privado transitorio con acceso exclusivo vía `service_role`.
- Se ejecutan en el servidor la sanitización de metadatos (EXIF) y el difuminado de rostros/patentes.
- La versión original se descarta y destruye inmediatamente al finalizar la transformación o ante cualquier fallo (comportamiento *fail-safe*).
- Únicamente la imagen anonimizada y sanitizada se persiste en el bucket final.

## 2. Requerimientos Funcionales
1. **RF-01 (Bucket de Cuarentena Privado)**: Creación del bucket `evidence-quarantine` en Supabase Storage con políticas de acceso RLS que impiden cualquier lectura pública.
2. **RF-02 (Edge Function de Cuarentena `quarantine-anonymize`)**: Función en Deno/TypeScript que:
   - Recibe la fotografía o referencia de cuarentena y `client_side_id`.
   - Limpia metadatos EXIF.
   - Aplica detección y difuminado en zonas sensibles (rostros y patentes).
   - Guarda la versión protegida en el bucket público final `report-evidences`.
   - Destruye la imagen cruda del bucket de cuarentena.
3. **RF-03 (Comportamiento Fail-Safe)**: Si ocurre un error de procesamiento, timeout o fallo de red, se purga de inmediato la imagen de cuarentena y se rechaza la operación, evitando que el archivo original quede expuesto o almacenado.
4. **RF-04 (Servicio Frontend `quarantinePipelineService.js`)**: Cliente que invoca la función o servicio de cuarentena, gestiona el estado de carga y devuelve la URL procesada a `ReportProcessingScreen`.

## 3. Criterios de Aceptación (Gherkin)
- **Escenario 1 (Procesamiento Exitoso)**: Dado que el usuario envía una fotografía capturada con conectividad, cuando entra al pipeline de cuarentena, entonces se sanitizan los metadatos, se difuminan las zonas sensibles, se guarda la imagen procesada en `report-evidences` y se destruye el original de `evidence-quarantine`.
- **Escenario 2 (Comportamiento Fail-Safe ante error)**: Dado que ocurre un error durante el procesamiento o difuminado de la imagen, cuando el pipeline detecta la excepción, entonces se destruye inmediatamente el archivo transitorio de cuarentena, no se persiste nada en almacenamiento público y se retorna un error controlado al cliente.
