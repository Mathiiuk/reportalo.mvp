# Specification — REP-3307: Configurar Ambiente Staging

## 1. Objetivo

Implementar y documentar un entorno de **Staging estable y permanente** para el Sponsor (**Carlos Ruiz**) y el Project Manager (**Leonel Nuñez**), con una URL fija en Vercel que sirva como referencia de las entregas consolidadas al final de cada Sprint o ciclo de desarrollo ([`docs/project/acta-de-inicio-v3.md:14-25`](https://github.com/Mathiiuk/reportalo.mvp/blob/main/docs/project/acta-de-inicio-v3.md#L14-L25)).

## 2. Problema actual

Actualmente, las ramas de desarrollo generan entornos *Preview* efímeros con URLs temporales para QA (Ivan Juarez). El Sponsor y el PM no cuentan con una URL fija y predecible que permanezca accesible en el tiempo para realizar demostraciones estratégicas, Sprint Reviews y validar el avance del MVP hacia Diciembre 2026.

## 3. Resultado esperado

1. Existencia de una rama permanente `staging` en GitHub.
2. Vinculación de un subdominio fijo en Vercel asignado a la rama `staging` (ej. `reportalo-staging.vercel.app`).
3. Validación automática de CI y Security en cada push a `staging`.
4. El Sponsor (Carlos Ruiz) dispone de un enlace permanente para evaluar el producto sin necesidad de credenciales de Vercel.

## 4. Alcance

### Incluido
- Configuración de la rama permanente `staging` en Git.
- Actualización de los workflows de GitHub Actions (`ci.yml` y `security.yml`) para validar `staging`.
- Guía paso a paso para asignar el subdominio de staging en Vercel Settings.
- Documentación del flujo de promoción: `feat/` → `staging` → `main`.

### No incluido
- Servidores dedicados on-premise (se aprovecha la red Edge de Vercel en plan Hobby).
- Bases de datos aisladas por entorno (se definirán en tareas posteriores al elegir el motor de base de datos).

## 5. Criterios de aceptación

- [ ] **AC-01**: La rama `staging` existe y está publicada en GitHub.
- [ ] **AC-02**: Los workflows `ci.yml` y `security.yml` se disparan automáticamente ante cambios en `staging`.
- [ ] **AC-03**: La URL fija de Staging en Vercel refleja los cambios mergeados a la rama `staging`.
- [ ] **AC-04**: El acceso al entorno de Staging es público y no requiere inicio de sesión en Vercel.
- [ ] **AC-05**: La bitácora y la wiki reflejan la arquitectura de los 3 entornos.

## 6. Restricciones

- **Plan Vercel Hobby**: La asignación de dominio por rama de Git es una característica nativa sin costo de Vercel.
- **Estabilidad**: La rama `staging` solo recibe código previamente probado y aprobado por Ivan Juarez en Previews.
