# Test Plan — REP-2908

## 1. Objetivo

Probar que el nuevo pipeline de RAG jurídico recupera fragmentos por significado real (vía un doble de prueba determinístico del cliente de embeddings, no por reglas de palabras clave) y que nunca genera una cita que no esté en el corpus recuperado.

## 2. Riesgos a validar

- Que no quede ningún camino de código que devuelva un fundamento sin pasar por la recuperación + validación determinística.
- Que el sistema falle cerrado (`indeterminado` / `sin_normativa`) ante: sin fragmentos sobre el umbral, cita no literal, `fragment_id` no recuperado, organismo inexistente, o error de la API de generación.
- Que la cascada jurisdiccional se exprese como parámetro de la consulta (RPC/SQL), no como matching de texto en JS.
- Que ningún test dependa de red real ni de claves de Gemini.

## 3. Unit tests

- [ ] Casos A–F de `docs/REP-3764_casos_esperados.md`, reescritos contra el nuevo pipeline con el doble de prueba de embeddings.

- [ ] Caso con cita que no aparece literal en el fragmento recuperado → `indeterminado`.
- [ ] Caso con `fragment_id` citado que no estaba entre los recuperados → `indeterminado`.
