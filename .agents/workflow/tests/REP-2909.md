# Test Plan — REP-2909

## 1. Objetivo

Verificar, sin depender de un Supabase real, que: la lógica de persistencia arma las filas correctas para `report_ai_analysis`/`report_ai_evidence`, las políticas RLS documentadas cubren los casos de aislamiento esperados, y la pantalla del ciudadano renderiza correctamente los 5 estados posibles del análisis (incluidos los de "fallo cerrado").

## 2. Riesgos a validar

- Que el borrado del mensaje de la cola nunca ocurra si la persistencia falló (para no perder reportes sin analizar).
- Que la pantalla del ciudadano nunca muestre texto de fragmentos `foundation_type_code = 'sancion'`.
- Que un estado `indeterminado`/`sin_normativa` se muestre de forma transparente, no como un error genérico ni oculto.
- Que las políticas RLS documentadas realmente restrinjan por dueño del reporte / organismo asignado (verificación manual, sin Supabase real disponible para un test automatizado).
