# Plan de Implementación: REP-2404 (Pipeline Server-Side de Cuarentena de Imágenes)

## Fases de Implementación

### Fase 1: Definición DDL y Políticas de Storage en Supabase
- Actualizar `supabase/schema.sql` con las definiciones formales de:
  - Bucket `evidence-quarantine` (privado, `public = false`).
  - Bucket `report-evidences` (público para visualización de evidencias protegidas, `public = true`).
  - Políticas de seguridad Storage RLS:
    - Inserción autorizada temporal en cuarentena.
    - Lectura denegada para público en cuarentena.
    - Acceso total para `service_role` (Edge Function).
    - Lectura pública exclusiva en `report-evidences`.

### Fase 2: Implementación de la Edge Function (`supabase/functions/quarantine-anonymize/index.ts`)
- Configurar la Edge Function con runtime Deno.
- Implementar pipeline modular:
  1. Sanitización de metadatos EXIF.
  2. Detección de rostros y patentes (con soporte de Google Vision y emulador de fallback seguro).
  3. Difuminado de zonas detectadas.
  4. Almacenamiento en `report-evidences`.
  5. Purgado forzoso de la imagen original en bloque `finally` / fail-safe.

### Fase 3: Servicio Frontend de Orquestación (`src/services/quarantinePipelineService.js`)
- Implementar el cliente para invocar el pipeline de cuarentena.
- Manejo de reintentos, timeout y fallback controlado en modo test o local sin credenciales.
- Documentar y comentar el código en español línea por línea.

### Fase 4: Integración en UI (`ReportProcessingScreen.jsx` y `NewReportPage.jsx`)
- Integrar la llamada real de cuarentena en `ReportProcessingScreen`.
- Actualizar el flujo de estados con soporte para reintento ante fallos fail-safe.

### Fase 5: Pruebas Automatizadas y Quality Gates
- Crear `src/test/QuarantinePipelineService.test.js` (unitarias).
- Crear `src/test/QuarantinePipelineFlow.test.jsx` (integración).
- Ejecutar `pnpm vitest run` y `pnpm run build`.
