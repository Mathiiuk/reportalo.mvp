# Implementation Plan — REP-3841

## 1. Resumen
Vulnerabilidad social: pedir la prestación (adultos / con niñas, niños o adolescentes), mostrar el canal del catálogo que devuelve `route_report` y quitar todo texto o paso que prometa una derivación. Sin tocar el motor.

## 2. Repositorio inspeccionado
- Stack: Vite + React 18 + Tailwind, Supabase
- Runtime: navegador (PWA)
- Package manager: pnpm
- Branch base: staging
- CI actual: Vitest (`pnpm test`)

## 4. Estrategia de implementación
`route_report` ya lee la prestación de `infraction_attribute_responses` y devuelve `accion: informar_canal` con el canal verificado. El frontend solo pregunta, guarda la respuesta antes de pedir el routing y muestra el resultado. Si no hay canal verificado, lo declara.

## 5. Migraciones / datos
Ninguna. La policy «insert own» de `infraction_attribute_responses` ya existe. El upsert es `ON CONFLICT DO NOTHING`.

## 6. Seguridad
Sin datos personales nuevos: la respuesta es una clave del catálogo. `route_report` solo le responde al autor.

## 7. Observabilidad
Si la prestación no se guarda, se registra un `console.error` y el reporte sigue enviado. En ese caso `route_report` propone el canal general y la pantalla lo muestra como no verificado.
