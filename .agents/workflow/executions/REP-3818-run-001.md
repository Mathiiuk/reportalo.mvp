## 1. Qué se implementó (`supabase/functions/analizar-imagen-reporte/`)
| Archivo | Responsabilidad |
|---|---|
| `contract.ts` | Esquema de salida, prompt `visual-v1`, `validateOutput`, `containsPersonalData`, `extractEvidencePath`, modelos. Puro, sin Deno. |
| `gemini.ts` | Llamada multimodal (imagen en línea, `responseSchema`, `thinkingLevel: low`), clave solo en `x-goog-api-key`, tiempo máximo de 20 s. `fetch` inyectado. |
| `analyze.ts` | Todo el flujo, con dependencias inyectadas (base, bucket, modelo, cola). |
| `index.ts` | Cableado de Deno: token del despachador, cliente Supabase, Gemini. |
| `redact.ts` | Copia de la redacción de claves de `analizar-reporte` (cada función se despliega autocontenida). |

**Flujo:** token `x-visual-dispatch-token` (tiempo constante) → `imageId` → evidencia + descripción + categoría + `client_side_id` de la base (el cuerpo se ignora) → si ya tiene resultado, se descarta el mensaje (no se paga otra llamada) → `VULNERABILIDAD_SOCIAL` queda `omitido` sin leer la foto ni llamar al modelo → ruta de la foto validada contra el `client_side_id` del reporte (solo `report-evidences`) → descarga, tamaño (≤ 10 MB) y formato → modelo principal (1 reintento) y, solo ante indisponibilidad, `gemini-3.7-flash` y `gemini-3.5-flash-lite` → validación determinística → segunda defensa contra datos personales → `persist_visual_analysis` y, solo si quedó guardado, borrado del mensaje.

**Falla cerrada.** Salida inválida, respuesta cortada o bloqueada, no JSON, 400 del modelo, resumen con dato personal, foto fuera de ruta / vacía / enorme / de formato no soportado: se guarda `fallido` con un motivo controlado (y modelo, prompt y consumo si el modelo respondió) y el reporte continúa. Errores **transitorios** (modelo no disponible, red, lectura del bucket, clave sin configurar, base): 503/500, no se guarda ni se borra nada; el despachador reintenta y tras 3 intentos deja `fallido` (REP-3817).

**No hace:** cambiar el estado o la categoría del reporte, emitir fundamento jurídico, escribir en `citizen_reports`, `report_ai_analysis` ni `knowledge_fragments`, ni modificar `analizar-reporte` (verificado por tests).

## 2. Decisiones
- Estructura con `analyze.ts` inyectable (en vez de todo en `index.ts` como `analizar-reporte`) para poder probar cada camino con Vitest sin Deno.
- `confidence_score` se guarda solo como observabilidad (REP-3816: vale 0,95 a 0,99 siempre).
- La discrepancia de categoría no se calcula acá: la pantalla (REP-3820) la deriva comparando `suggested_service_id` con la categoría del reporte (hallazgo 2 de REP-3816).
- El prompt agrega la regla de REP-3816 contra rasgos físicos y condiciones de salud.
- 401/403 se tratan como indisponibilidad (configuración), no como un problema de la foto: no se guarda `fallido` por una clave mal cargada.
